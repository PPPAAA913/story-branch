# 写作方法与提示词适配

2026-11-12 · 王司恺 · 对应方法包版本 `2026-11-11.1`

这份文档回答两个问题：服务端到底用了哪些写作方法；我们的模板和它是什么关系、改了什么。

## 1. 来源与许可证

- 上游：`ur-grue/autopunk-media-skills`，MIT 许可证。
- 采用五项：character-profile-writer、beat-sheet-builder、scene-writer、dialogue-polisher、script-notes-writer。
- 未引入上游示例故事、长片节拍表、固定页数或百分比；未安装第三方插件、未运行第三方脚本。
- 来源 URL、git blob SHA 与许可证见 `third_party/autopunk-media-skills/sources.json` 与同目录 `LICENSE`；代码中的适配位于 `studio/writing.py`。

## 2. 五个方法怎么改成短剧规则

| 方法 | 上游关注 | 本项目适配 | 用在哪些阶段 |
|---|---|---|---|
| 人物动机与口吻 | 外部目标/内在需要、弱点、口吻 | 区分 want 与 need；弱点落实为压力下可观察的选择；写清人物知道/不知道什么；给出句长、词汇、回避方式、沉默习惯和一句原创英文示例；不强行给每个人加创伤 | 方向、人物、大纲、剧本、审阅 |
| 因果与情节节拍 | 节拍、因果、代价 | 每个节拍写清谁做了什么、遇到什么阻力、付出什么代价、局面如何改变；反转要有铺垫；不靠重复误会；按 60–90 秒组织，不套长片十五节拍 | 方向、大纲、审阅 |
| 可拍摄的场景 | 场景目标、变化、格式 | 每场写清进入时的局面、各人目标、阻力、离开时的变化；INT./EXT.、现在时英文动作、人物名与对白；动作必须可见可听；遵守演员/场地/道具限制 | 首集剧本 |
| 对白与潜台词 | 潜台词、口吻、自然度 | 判断台词是在争取、试探、回避还是掩饰；减少解释情绪的句子；按人物区分词汇、节奏与沉默；保持目标地区英语，避免直译和刻板印象；润色不改剧情事实 | 首集剧本、审阅 |
| 有依据的改稿审阅 | 证据、优先级 | 先指出最影响本稿的核心问题；每条含真实短引文或场次定位、问题、原因、可执行修法；列值得保留的内容与最多三项优先修改；不把主观评价说成市场验证 | 修改与对比 |

## 3. 阶段映射与注入方式

| 阶段 | 注入的方法 |
|---|---|
| 创作简报 | 无（只有简报输出要求） |
| 故事方向 | 因果与情节节拍；人物动机与口吻 |
| 人物设定 | 人物动机与口吻 |
| 前三集大纲 | 因果与情节节拍；人物动机与口吻 |
| 首集剧本 | 可拍摄的场景；对白与潜台词；人物动机与口吻 |
| 修改与对比 | 有依据的改稿审阅；因果与情节节拍；人物动机与口吻；对白与潜台词 |

方法包由服务端拼接进系统提示，**不是**模板的一部分。每次生成保存 `version / mode / stage / skills / instructions / sha256 / upstream_versions`，可在版本记录里核对。

## 4. 提示词适配原则

1. **分层，不重复**：方法包管写作方法（团队维护、改代码）；模板管项目约束（王司恺维护、改内容）；简报管单个案例的事实。
2. **模板不越权**：模板不能改变任务模式；只讨论、只审阅由服务端强制保持原稿；模板里的改稿指令不能压过模式。
3. **模板补方法包不覆盖的**：目标地区、时长、演员/场地、语言、必须包含/避免、验收点、已知问题。
4. **不编造**：受众写成“核心受众假设（待验证）”；不写市场数据、平台规则或行业结论。
5. **可追溯**：方法包有版本号，模板有 `阶段－目的－版本`，简报有项目代号；改版必须写依据。

### CASE-001 的适配示例

- 简报模板补了“类型与语气”“已确定/待确认”，对应 `OUTPUTS["brief"]`。
- 方向模板补了“压力下的选择与代价”，对应 beat-sheet 与 character 两条规则。
- 剧本模板明确“英文正文 + 中文梗概、不写第二集、保持人物知识与大纲因果”，对应 `OUTPUTS["script"]` 与 scene/dialogue 规则。
- 审阅模板补了“保留项、需要人决定的问题”，对应 script-notes 规则。

## 5. 已验证与未验证

**已验证**：规则映射、快照字段、四种模式的服务端行为、样例模式六阶段流程（39 项自动化测试 + 本机演示项目）。

**未验证**：真实模型下的写作质量、模板 v1 与 v2 的差异、CASE-002/003 的泛化表现。样例模式输出固定，不能用来评分。

**边界**：单次生成有随机性；对照试写只作探索性比较，不宣称提升比例或统计显著；不把模板效果写成行业验证。
