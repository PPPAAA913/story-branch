# 验收与对照（王司恺 × 吕兴治）

## 1. 每阶段看什么

| 阶段 | 必过项 | 不合格信号 |
|---|---|---|
| 创作简报 | 地区具体到城市语境；时长/集数/演员/场地齐全；未知项标待确认 | 写成剧情梗概；补造预算或平台数字；“欧美”一笔带过 |
| 故事方向 | 三案在欲望/对抗/引擎上至少两项不同；钩子可拍 | 三案同构；提前写剧本；把假设写成结论 |
| 人物设定 | want 与 need 互相拉扯；对手有合理目标；英文口吻可区分 | 人物小传；所有角色一个腔调；人数超编 |
| 前三集大纲 | 三集递进；转折由人物选择驱动；不超演员/场地 | 三集平行；靠误会拖延；第 3 集收太早 |
| 首集剧本 | 正文全英文；中文梗概准确；时长与场次达标；不超限制 | 中文混入正文；场次过多；对白解释性 |
| 修改与对比 | 意见能定位到片段；硬问题与偏好分开；原稿不变 | 空泛评价；顺手改稿；把评分当市场预测 |

## 2. 片段记录表

每个案例至少记 3 条“满意”和 3 条“不满意”，必须引用实际文字，不写“整体不错”。

| 编号 | 案例/阶段/版本 | 片段原文（≤50 字） | 判断（满意/不满意） | 问题类型 | 建议 | 是否已反馈给彭奥/赵哲 |
|---|---|---|---|---|---|---|
| W-001 | CASE-001 / 人物 / V3 |  |  | 动机 / 口吻 / 因果 / 制作 / 语言 |  |  |

问题类型只用这五类：人物动机、因果逻辑、英文口吻、制作可行性、中文梗概忠实度。其他问题单独写在下面。

## 3. 对照试写（与吕兴治）

依据 `WRITING_SKILLS.md` 的对照方案，使用仓库自带脚本：

```powershell
.\.venv\Scripts\python.exe -m studio.evaluate_writing
```

- 默认只准备三组任务，**零 API 调用**，结果在 `data/writing-evaluation/`。
- 真实密钥由彭奥配置后，才由操作者显式运行 `--live`；每轮最多六次调用，无自动重试。
- 三组分别看：人物口吻/潜台词、连续性/因果、制作限制/开场悬念。

### 分工

- **王司恺**：检查测试简报、规则是否按阶段生效、期望行为是否写清；确认 `blind_samples.json` 里样本可读、没有泄露分组。
- **吕兴治**：组织至少两位组员盲评，按六个维度各打 1–5 分并引用片段：人物一致性、因果、口吻、制作约束、英语自然度、梗概忠实度。**评分完成后再看 `assignment.json`**。
- 两人一起把结果写进汇报，注明“单次探索性比较，不构成统计显著结论”。

## 5. 边界

- 样例模式是固定文本，**不能**用来评价模型写作质量。
- 真实 API 接通前，只检查流程与模板可执行性，不打“质量分”。
- 单次生成有随机性；三组单次试写只能作探索性比较，不能宣称提升比例或统计显著。
- 不把原创测试简报写成市场调研，也不把模板效果写成行业验证。
