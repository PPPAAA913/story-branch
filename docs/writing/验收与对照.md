# 验收与对照（王司恺 × 吕兴治）

## 1. 每阶段看什么

| 阶段 | 必过项 | 不合格信号 |
|---|---|---|
| 创作简报 | 地区具体到城市语境；类型与语气明确；时长/集数/演员/场地齐全；已确定与待确认分开 | 写成剧情梗概；补造预算或平台数字；“欧美”一笔带过 |
| 故事方向 | 三案在欲望/对抗/代价/引擎上至少两项不同；钩子可拍 | 三案同构；提前写剧本；把假设写成结论 |
| 人物设定 | want 与 need 互相拉扯；对手有合理目标；英文口吻可区分 | 人物小传；所有角色一个腔调；人数超编 |
| 前三集大纲 | 三集递进；每集有选择与代价、反转铺垫、下一集因果；不超演员/场地 | 三集平行；靠误会拖延；第 3 集收太早 |
| 首集剧本 | 正文全英文；中文梗概准确；时长与场次达标；不超限制 | 中文混入正文；场次过多；对白解释性 |
| 修改与对比 | 有保留项；意见能定位到片段；硬问题与偏好分开；原稿不变 | 空泛评价；顺手改稿；把评分当市场预测 |

## 3. 对照试写（与吕兴治）

仓库脚本 `studio.evaluate_writing` 已内置三组配对任务，比较“普通提示词（baseline）”与“方法包（skills）”，同一模型、简报、上游与指令。默认零调用；`--live` 最多 6 次，不自动重试。

| 组 | 重点 | 检查点 |
|---|---|---|
| voice-and-subtext | 人物口吻 / 潜台词 | 两人口吻可区分；动作和对白承担潜台词；Maya 通过看文件才知道条款；只用 2 名演员、1 个场景 |
| continuity-and-causality | 连续性 / 因果 | Nora 不凭空知道姓名；不把“搬走”升级成“死亡”；揭示源于核对与追问；不新增第三名出镜角色 |
| production-and-hook | 制作限制 / 开场悬念 | 开场以可见事件引出问题；无手机、额外人物或外景；交易推动反转；中文梗概不补写英文稿没有的情节 |

### 流程

1. 王司恺先跑 `python -m studio.evaluate_writing`（无 API），检查 `plan.json` 三组任务与 `checks` 是否可读、`blind_samples` 是否会泄露分组。
2. 彭奥配置密钥后，操作者显式加 `--live`，最多 6 次调用；失败记录进 `errors.json`，不重试掩盖。
3. 吕兴治组织至少两位组员盲评 `blind_samples.json`，按六维度 1–5 分并引用片段；**评分完成后再看 `assignment.json`**。
4. 两人把结果写进汇报，注明“单次探索性比较，不构成统计显著结论”。

**注意**：这个脚本比较的是“baseline vs 方法包”，不是“我们的模板 v1 vs v2”。模板版本对比要另做：同一简报、同一模型各跑一次，再用同一张评分表盲评。

### 模板 v1/v2 复跑（预算允许时）

- 只做 CASE-001 首集：v1 一次、v2 一次，同一模型、同一简报、同一上游。
- 用同一张评分表盲评，比较六维度；不跑 CASE-002/003 的 v1/v2，保留为留出集。

## 5. 边界

- 样例模式是固定文本，**不能**用来评价模型写作质量。
- 真实 API 接通前，只检查流程与模板可执行性，不打“质量分”。
- 单次生成有随机性；三组单次试写只能作探索性比较，不能宣称提升比例或统计显著。
- 不把原创测试简报写成市场调研，也不把模板效果写成行业验证。
