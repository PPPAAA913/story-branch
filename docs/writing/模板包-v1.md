# 提示词模板包 v1（六阶段）

用法：登录后在“提示词库 → 修改并另存”创建，标题照抄下方“模板标题”。正文直接粘贴。模板只补内容约束，人物/节拍/场景/对白/审阅方法由服务端写作方法包自动注入，不要重复抄写。

---

## 1. 简报－制作约束－v1

**适用阶段**：创作简报

**正文**

```text
【任务】把用户的想法整理成中文创作简报，供后续五个阶段引用。
【必填字段】目标英语地区（具体到国家/城市语境）、类型与语气、核心受众假设、对白语言与梗概语言、单集时长、集数、演员上限、场地上限、制作限制、必须包含、必须避免、已确定事项、待确认事项。
【规则】
- 只写可执行信息，不写完整剧情；故事种子不超过 5 句。
- 简报没给的数字不要编，统一写“待确认”。
- 地区要具体到能判断用语的程度（例如英国伦敦、澳洲悉尼），不要只写“欧美”。
- 受众写成“核心受众假设（待验证）”，不写成调研结论。
- 不写市场数据、平台策略、发行建议。
【输出】一份中文简报，800 字以内，优先用表格。
```

**输入例子**：一段 3 句话的故事种子 + “美国中西部，3 集，每集 75 秒，3 个演员，2 个场地，单机位”。

**预期结果**：字段齐全；地区具体；类型与语气明确；已确定/待确认分开；“待确认”明确；没有编造的预算或市场数字。

**已知问题**：容易扩写成剧情梗概；把“美国”泛化成“欧美”；自行补预算、平台或集数。

## 2. 方向－三案差异－v1

**适用阶段**：故事方向

**正文**

```text
【任务】基于已确认简报，提出 3 个故事方向，供人选择。本阶段不写大纲和剧本。
【差异要求】三个方向至少在两项上不同：主角欲望、核心对抗关系、叙事引擎（观众为什么追下一集）。
【每个方向写】标题、logline（不超过 40 字）、主角与对手各自要什么、主角在压力下做的选择与付出的代价、核心冲突、开场 5 秒钩子（必须是可以拍出来的画面或动作）、三集结尾钩子各一句、制作难点、观众假设（待验证，不写数据）。
【禁止】三案同构；编造行业数据；超出演员与场地上限；把“待验证假设”写成结论。
【输出】中文。最后用一张表对比三案的欲望、对抗、代价、引擎。
```

**输入例子**：已确认的 CASE-001 简报 + “给我三个方向”。

**预期结果**：三案在欲望/对抗/代价/引擎上明显不同；钩子可拍；合规；末尾有对比表。

**已知问题**：三案只是换职业或换名字；提前写剧本；钩子写成抽象概括。

## 3. 人物－动机口吻－v1

**适用阶段**：人物设定

**正文**

```text
【任务】基于已确认的故事方向，建立人物设定。只写人物，不写大纲。
【每个角色写】已确认事实（姓名/年龄/身份/关系/已发生的事）、外部目标（这一集具体要什么）、内在需要（自己没意识到的缺口）、弱点与恐惧、压力下的选择（可观察）、秘密以及谁知道、知识边界（此刻知道什么/不知道什么）、关系三句话（谁要什么 / 谁挡谁 / 观众站谁）、可观察的行为习惯、人物弧光（第 1 集到第 3 集的变化）、英文口吻样本 3 句。
【约束】角色数量不超过简报的演员上限；不要给每个角色强加创伤；口吻样本要能看出身份与教养差异；不新增未批准的主要角色。
【输出】中文设定 + 英文口吻样本。
```

**输入例子**：选定方向 A + CASE-001 简报 + “做人物设定”。

**预期结果**：want 与 need 互相拉扯；对手有合理目标；口吻样本可区分；人数不超编。

**已知问题**：写成人物小传；want 与 need 混为一谈；所有角色说话一个味。

## 4. 大纲－因果递进－v1

**适用阶段**：前三集大纲

**正文**

```text
【任务】写前三集大纲，每集一个独立段落。
【每集写】开场事件（0–5 秒钩子）、冲突行动、主动选择与代价、反转的铺垫、结尾悬念、信息增量（观众新知道什么）、与下一集的因果连接、制作提示、预计秒数（创作估计，不代表实拍）。
【因果要求】每个转折写清“因为上一集发生了什么，所以这一集必须……”。禁止用误会、巧合、失忆、手机没电反复拖延。
【递进要求】第 1 集建立欲望与障碍；第 2 集代价升级并揭露改变判断的新信息；第 3 集迫使主角做出不可逆选择，留下续看钩子。
【约束】不超演员与场地上限；超出的想法写“待确认”，不要直接写进大纲。
【输出】中文。每集末尾标出主角 want 与 need 如何拉扯。
```

**输入例子**：CASE-001 人物设定 + “写前三集大纲”。

**预期结果**：三集递进；转折由人物选择驱动；每集有钩子与信息增量；不超制作限制。

**已知问题**：三集平行；第 3 集把矛盾收干净；靠误会推动；场地越写越多。

## 5. 剧本－英文首集－v1

**适用阶段**：首集剧本

**正文**

```text
【任务】写第一集完整英文剧本，文末另附中文梗概。
【格式】英文剧本：场次号、INT./EXT.、地点、日/夜、在场人物、动作描述、英文对白。正文全部英文；中文只出现在文末梗概，不得混入正文。
【时长】按简报执行；每场标注创作估计秒数（不代表实拍），并在开头标注总时长；简报没写时按 60–90 秒处理并标“待确认”。
【约束】保持已确认人名、人物知识、时间线与大纲因果；不写第二集；中文梗概必须与实际剧情一致；不新增未批准的角色与场地；无特技、无真实品牌；对白短句化，符合人物身份与此刻目的，避免解释性台词。
【自检】正文是否还有中文？是否超出演员/场地？结尾是否停在第 1 集悬念？
【输出】制作抬头（总时长/场次/演员/场地）+ 英文剧本 + 中文梗概（150 字以内）。
```

**输入例子**：CASE-001 大纲第 1 集 + “写首集剧本”。

**预期结果**：正文全英文；场次与秒数清楚；80 秒左右；中文梗概准确；不超限制。

**已知问题**：中文动作混进英文剧本；场次过多导致超时；对白解释性强；梗概写成剧情复述。

## 6. 审阅－证据式意见－v1

**适用阶段**：修改与对比（配合“只审阅”模式）

**正文**

```text
【任务】审阅当前首集剧本，只提意见，不改稿。
【每条写】位置（场次号，或引用不超过 30 字的原文）、问题、原因、可执行改法、严重度（高/中/低）。
【分类】硬问题（逻辑断裂、违反简报、不可拍）与偏好问题（风格选择）分开列。
【保留】先列出值得保留的内容，避免只挑错。
【优先】最后给出前三项优先修改，并说明先改哪一项；另列需要人决定的问题。
【禁止】泛泛而谈；给市场效果打分或预测；直接改写原文；把主观偏好说成硬错误。
【输出】中文审阅记录。创作/修改模式写入本阶段 document；只审阅模式只放 reply。
```

**输入例子**：CASE-001 首集剧本 + 任务模式选“只审阅”。

**预期结果**：每条都能定位到片段；建议可执行；硬问题与偏好分开；原稿不变。

**已知问题**：空泛评价；顺手改稿；把 1–5 分说成市场效果；遗漏制作限制。

---

## 命名与版本

- 标题格式：`阶段－目的－版本`，例如 `人物－动机口吻－v1`。
- 改动模板时新建版本，不覆盖旧版：`人物－动机口吻－v2`，并在 `验收与对照.md` 写清改因。
- 全组共享同一个在线服务时，模板对全员可见；本机安装的模板不会自动同步给别人。
