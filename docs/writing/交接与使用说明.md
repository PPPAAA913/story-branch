# 交接与使用说明

2026-11-12 · 王司恺

## 0. 先分清两类东西

| 内容 | 在哪里 | 谁会用 |
|---|---|---|
| 简报、模板正文、写作方法、验收与对照 | Git 仓库 `docs/writing/` | 所有人可直接阅读 |
| 六个自定义模板（成品） | 服务数据库 | 需要在目标服务里创建一次 |
| 演示项目 CASE-001 | 服务数据库 | 需要在目标服务里创建一次 |

**Git 只带文档，不带数据库。** 换一台电脑、换一个服务，模板和项目都不会自动出现。共享服务上线后，需要有人登录一次，把这两样“落地”。

## 1. 上线后的一次性落地（王司恺，约 10 分钟）

1. 用 `wang_sikai` 登录共享服务。
2. 打开“提示词库”，选一个内置模板，点“修改并另存”。
3. 标题、分类、正文照下表填写，六个都建一次。
4. 新建项目，名称 `演示 · CASE-001 美国中西部`，粘贴 `简报-001.md` 第 1 节的内容，检查后确认简报。
5. 检查：模板库应显示 12 条（6 内置 + 6 自定义）；演示项目状态为“简报已确认”，其余阶段为空。

| 顺序 | 阶段 | 模板标题 | 分类 |
|---|---|---|---|
| 1 | 创作简报 | `简报－制作约束－v1` | 简报 |
| 2 | 故事方向 | `方向－三案差异－v1` | 创意 |
| 3 | 人物设定 | `人物－动机口吻－v1` | 人物 |
| 4 | 前三集大纲 | `大纲－因果递进－v1` | 大纲 |
| 5 | 首集剧本 | `剧本－英文首集－v1` | 剧本 |
| 6 | 修改与对比 | `审阅－证据式意见－v1` | 审阅 |

正文在 `模板包-v1.md`，每个模板的 `text` 代码块可整段复制。

## 2. 各角色怎么用

### 吕兴治（功能测试）

- **不需要我们的自定义模板。** 内置模板已经带写作方法包，足够验证登录、权限、六阶段、分支、冲突、导出。
- 功能验收按 `VALIDATION.md`；内容检查按 `验收与对照.md` 第 1 节。
- 内容检查用 CASE-001，记录“满意/不满意”的实际片段，不要用样例模式打分。
- 对照试写时，先跑 `python -m studio.evaluate_writing`（零 API 调用），确认三组任务可读；`--live` 由彭奥配置密钥后执行，最多 6 次。

### 彭奥 / 赵哲（API 与集成）

- 用 CASE-001 做真实 API 冒烟：**先只跑“故事方向”一阶段**，确认请求成功、`document` 非空、版本保存；再跑完整六阶段。
- 对照 `演示案例-CASE-001.md` 的“预期结果”判断是否跑偏；失败时保留原始返回，交给王司恺记录。
- 模板要在共享服务里建好才可见；他们本机测试可以只用内置模板，不必等模板。
- 真实 API 前先看 `API联调提醒-给彭奥.md`，尤其是 `max_tokens` 和 `thinking`。

### 王司恺（内容与评分）

- 负责第 1 节的落地；跑 CASE-001 基线；记录片段；改模板到 v2。
- 先评分再迭代；CASE-002/003 留作留出集，v2 冻结后再各跑一次。
- 与吕兴治一起看 `blind_samples.json`，评分完成前不看 `assignment.json`。

### 徐晓栋（汇报）

- 用共享服务里的演示项目导出整条路线，或直接读 `演示案例-CASE-001.md`。
- 不需要模板，也不需要在 Web 里操作；重点是能讲清“创作中有什么困难 → 工作台怎么支持 → 我们实际测到了什么”。

## 3. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 看不到六个模板 | 只在王司恺本机建过；自定义模板不随 Git 走 | 在目标服务按第 1 节重建 |
| 看不到演示项目 | 各自本机数据库不共享 | 用彭奥的共享服务，或自己在本地建 |
| 样例输出和 CASE-001 不一致 | 样例是固定文本，不读取简报细节 | 正常；真实 API 接通后再看内容 |
| 模板重复 | 有人重复“修改并另存” | 先搜索标题，再建；重复的删除或改名 |
| 下游不能生成 | 上游未确认 | 先保存并确认上一阶段 |
| 审阅阶段确认失败 | 只审阅不改稿，阶段稿件为空 | 选“创作/修改”生成记录，或手动写审阅记录再确认 |

## 4. 建议的验收顺序

1. 文档齐：写作方法、提示词适配、对照试写方案都在 `docs/writing/`。
2. 共享服务里 12 条模板齐全。
3. 演示项目简报已确认。
4. 真实 API 单阶段冒烟通过。
5. CASE-001 六阶段基线完成，片段记录有内容。
6. 盲评完成，评分与片段对应。
7. 模板 v2 + CASE-002/003 留出验证。
8. 11/18 冻结演示版本。

任何一步没通过，不要跳到下一步；尤其不要在样例模式下给模型质量打分。
